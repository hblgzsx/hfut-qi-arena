# 功能逻辑核查与修正（2026-11-27）

本次按“创建 → 配裁判 → 导入检录 → 抽签 → 调度 → 录分 → 归档”的实际流程核查。测试使用模拟名单和账号，数据库验证在事务中回滚；未为现场真实账号重置密码。

## 发现并修复

| 问题 | 处理后的行为 | 验证 |
| --- | --- | --- |
| 创建比赛与赛事密码脱节 | 创建第一步必填密码并再次确认，服务端同样校验；比赛和密码同一事务保存，失败整体取消 | 密码单元测试、创建浏览器流程、云端 SQL 事务验证 |
| 调度页开头先填写验证内容，操作对象不明确 | 先编辑，点击保存或执行敏感操作后弹出对应操作的确认窗口，验证成功才提交；取消不提交 | 调度浏览器测试，检查请求数量与修改前后状态 |
| 重新导入报名名单仍残留旧队列和叫号 | 无现场对局时清空旧签位调度、队列和叫号，保留桌数和裁判；已叫号或开赛时阻止替换 | 调度单元测试 |
| 自动刷新覆盖正在编辑的候场顺序 | 草稿保留，另一个管理员改变该顺序时提示冲突，要求加载新安排 | 前端草稿与服务器版本分别校验 |
| 裁判编排异步新建账号时可能使用旧草稿 | 添加裁判使用当前编排状态，保留已有的并发修改检查 | 创建、配置流程回归 |
| 裁判信息导出固定包含密码 | 管理员选择裁判和字段，密码默认不勾；既有不可读取的密码明确标记，不自动重置 | 数据单元测试、读取实际 TXT/XLSX 文件验证 |
| 部分导出被当作整批密码已保存 | 按已导出密码的邮箱逐人记录；不含密码或只导出部分人员，关闭时仍提醒保存剩余密码 | 账号导出浏览器测试 |

## 核对的前置条件与权限

- 未选择有效赛事不展示调度工作台；切换赛事重新读取，并清空上一场页面草稿。
- 新比赛每张启用棋盘至少一名裁判；同赛事一名裁判一桌、同桌可多人。空绑定不会被当作已分配裁判。
- 非管理员看不到账号导出、裁判配置、创建、删除、备份与恢复入口；后端独立校验角色。
- 裁判需登录并验证当前赛事密码，且仅能操作自己绑定棋盘的对局。比赛时间结束后停止裁判提交；已结束成绩由管理员更正。
- 未到场者在抽签前移出名单；优先选手仅调整第一轮的上场顺序，不改变随机产生的对手和轮空。
- 桌数限制、兼项不冲突、完赛补台、休息 180 秒后跨轮开赛，继续由调度引擎统一判断。
- 修改抽签与顺序要验证赛事密码并记录原因；下游已叫号或进行中时阻止影响该对局的上游更正。
- PDF、群通知不包含账号密码；账号导出是管理员单独操作。赛事密码不进入普通赛事状态或 JSON 备份。
- 自动备份默认关闭、默认 10 分钟，可随时修改；本机副本需要管理员页面打开。云端任务独立于页面运行。

## 本次验证结果

46 项单元测试通过，覆盖密码、权限、赛程、裁判绑定、重导名单、补台休息、成绩与更正、备份结构及导出字段。

5 个浏览器回归脚本通过：

1. `credential-export-browser.mjs`：选择裁判、字段、密码，核对实际下载文件；部分保存提醒；不重置旧密码。
2. `operations-browser.mjs`：页首无密码表单，编辑和取消不提交，错误密码不改状态，验证成功保存并叫号。
3. `workspace-browser.mjs`：创建必填密码、确认一致、按桌配裁判、创建账号、PDF/打印、切换赛事与无效赛事隔离。
4. `role-visibility-browser.mjs`：观众、待授权账号、裁判均无管理员导出和管理入口；裁判只见负责对局。
5. `auto-backup-browser.mjs`：开关、间隔、本机副本、云端下载和关闭后的配置保留。

前端构建、Deno 后端类型检查通过。云端 SQL 验证：无效密码不留下赛事、成功创建即具备可验证密码、赛事状态中无密码；验证数据已回滚。

浏览器业务流程主要使用模拟后端回包；数据库事务逻辑在实际 Supabase 数据库验证。未进行真实 15 桌多设备同时操作和现场音响试听，这两项仍建议赛前彩排确认。
